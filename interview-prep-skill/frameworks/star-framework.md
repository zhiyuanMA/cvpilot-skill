# STAR / CAR / SOAR — Structure Selection

Reference framework for Stage 4 (`prompts/04-bq-prep.md`).

## Three structures, when to use which

| Structure | Shape | Best for |
|---|---|---|
| **STAR** | Situation · Task · Action · Result | The default. Most behavioral questions work fine with this. |
| **CAR / PAR** | Challenge (Problem) · Action · Result | When the answer needs to land faster — phone screens, quick-fire rounds. Drops the lengthy setup. |
| **SOAR** | Situation · Obstacle · Action · Result | Questions that specifically want to hear about a hard obstacle — "biggest challenge," "how did you push through adversity." |

Rule of thumb: **prepare the full STAR version** (it captures everything), and trim it to CAR/SOAR shape on the fly depending on how the question is actually phrased in the interview.

## Spoken delivery — time budget (60–90 seconds)

```
S  ▓             ~15%   one or two sentences, just enough to orient the listener
T  ▓▓            ~15%   pin down what YOU specifically were responsible for
A  ▓▓▓▓▓▓        ~50%   the core of the answer — judgment calls and trade-offs
R  ▓▓▓           ~20%   quantified result + a one-line reflection
```

The most common failure mode: Situation eats up half the answer and Action gets one sentence. **Time budget should always lean toward Action** — that's where the actual signal is.

## One story, many questions

A well-developed story can usually answer 5–8 different questions — the trick is changing the opening line and the closing emphasis while the core Action stays the same.

Example — a story about "persuading a team to abandon a plan they'd already invested in":

| Question asked | Open by emphasizing | Close by emphasizing |
|---|---|---|
| Tell me about a conflict | the disagreement in judgment | how alignment was reached |
| A time you influenced without authority | having no formal authority | how data/trust did the persuading |
| A time you took ownership | initiating the pushback yourself | owning the outcome |
| A data-driven decision | the use of data | how the data changed the outcome |
| Your biggest failure (if there's a lesson in it) | an early misjudgment | what changed afterward |

When tagging a story to a competency, always also note **which other questions this same story could answer** — that's the direct payoff of building a small set of well-developed stories instead of a new one for every question.

## Delivery format

Write the prepared answer as a spoken, first-person, interview-ready version (60–90 seconds), using bolded S/T/A/R labels so it's easy to scan while rehearsing.
